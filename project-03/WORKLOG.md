# PROJECT 03 작업 기록

## 1. 프로젝트 개요

Google Form으로 프로그램 만족도와 상담 요청을 수집하고, 응답을 Google Sheets에 저장한 뒤 Make와 Zapier를 이용하여 조건별 이메일 알림을 자동 발송하는 프로젝트이다.

Make에는 NVIDIA AI API를 추가로 연결하여 만족도가 낮은 응답의 개선사항을 요약한 뒤 이메일로 발송하는 보너스 기능도 구현하였다.

### 2026-07-25~07-29 — Make 기본 자동화 구현

#### 자동화 구조

```text
Google Form
→ Google Sheets
→ Make Watch New Rows
→ Router
   ├─ 상담 요청 = 예 → Gmail 상담 요청 알림
   └─ 만족도 ≤ 2점 → Gmail 낮은 만족도 알림
```

#### 수행 내용

1. Google Sheets의 `Watch New Rows` 모듈 생성
2. 설문 응답이 저장되는 스프레드시트와 워크시트 연결
3. Router를 추가하여 처리 경로를 두 개로 분리
4. 상담 요청 분기에 `상담 요청 = 예` 필터 설정
5. 낮은 만족도 분기에 `만족도 ≤ 2점` 필터 설정
6. 각 분기에 Gmail 모듈 연결
7. 설문 응답 정보를 이메일 제목과 본문에 매핑
8. `Run once`를 이용하여 조건별 이메일 발송 테스트

#### 발생한 문제

- 초기 설정에서 기존 행과 새 행의 시작 위치를 지정하는 과정이 혼동됨
- Router의 Fallback 안내로 인해 분기 구조를 다시 확인함
- 필터에 표시되는 Google Sheets 열과 매핑값을 찾는 과정에서 어려움이 있었음
- 일부 테스트에서 이메일 제목과 본문이 의도한 값으로 표시되지 않음
- 설정 오류로 Make 시나리오를 새로 작성함

#### 해결 방법

- Google Sheets 연결과 시작 위치를 다시 설정함
- Router의 각 경로에 필터를 개별 적용함
- 실제 테스트 응답을 추가하여 새로운 행이 감지되는지 확인함
- Gmail 제목과 본문 필드를 다시 매핑함
- 상담 요청과 낮은 만족도 조건을 각각 테스트함
- 두 조건을 동시에 충족하는 응답으로 두 분기의 동시 실행을 확인함

#### 결과

- 상담 요청이 `예`인 경우 상담 요청 이메일 자동 발송 성공
- 만족도가 `2점 이하`인 경우 낮은 만족도 이메일 자동 발송 성공
- 두 조건을 모두 충족하면 이메일 두 통이 각각 발송되는 것을 확인함

### 2026-07-29~07-30 — Zapier 자동화 구현

Zapier 무료 플랜에서는 Paths를 이용한 다중 조건 분기가 제한되어 있어, 하나의 자동화를 두 개의 Zap으로 나누어 구현하였다.

#### Zap 1: 상담 요청 알림

```text
Google Sheets 새 행 감지
→ 상담 요청 = 예 필터
→ Gmail 상담 요청 알림 발송
```

#### Zap 2: 낮은 만족도 알림

```text
Google Sheets 새 행 감지
→ 만족도 ≤ 2점 필터
→ Gmail 낮은 만족도 알림 발송
```

#### 수행 내용

1. Google Sheets의 `New Spreadsheet Row` 트리거 설정
2. 설문 응답 스프레드시트와 워크시트 선택
3. 테스트용 설문 응답 불러오기
4. 상담 요청이 `예`인 경우만 통과하도록 Filter 설정
5. Gmail 알림 제목과 본문 매핑
6. 상담 요청 Zap 테스트 및 활성화
7. 기존 Zap을 복사하여 낮은 만족도 Zap 생성
8. 만족도가 `2점 이하`인 경우만 통과하도록 조건 변경
9. 낮은 만족도 Zap 테스트 및 활성화

#### 발생한 문제

- 무료 플랜에서는 하나의 Zap 안에서 두 조건을 자유롭게 분기하기 어려웠음
- Zap 복사 후 일부 필터와 이메일 내용을 다시 수정해야 했음
- 테스트용 응답 선택과 Zap 공개 시점을 구분하는 과정에서 혼동이 있었음

#### 해결 방법

- 상담 요청과 낮은 만족도 알림을 별도의 Zap 2개로 구성함
- 각 Zap의 필터와 Gmail 내용을 따로 설정함
- 테스트 완료 후 두 Zap을 각각 활성화함

#### 결과

- 상담 요청 알림 이메일 수신 성공
- 낮은 만족도 알림 이메일 수신 성공
- 두 조건을 모두 충족하는 응답에서는 두 Zap이 각각 실행되는 것을 확인함

### 2026-07-30~08-01 — NVIDIA AI 보너스 기능 구현

Make의 낮은 만족도 분기에 NVIDIA AI API를 연결하여, 설문에 작성된 개선사항을 요약한 뒤 이메일로 발송하도록 확장하였다.

#### 최종 자동화 구조

```text
Google Form
→ Google Sheets
→ Make Watch New Rows
→ Router
   ├─ 상담 요청 = 예
   │  └─ Gmail 상담 요청 알림
   │
   └─ 만족도 ≤ 2점
      └─ NVIDIA API 개선사항 요약
         └─ Gmail AI 요약 알림
```

#### 수행 내용

1. NVIDIA Build에서 사용할 AI 모델 확인
2. Make에 HTTP 요청 모듈 추가
3. NVIDIA API 요청 주소와 인증 헤더 설정
4. 설문 개선사항을 프롬프트에 매핑
5. JSON 형식의 요청 본문 작성
6. NVIDIA API 응답 결과 확인
7. AI가 생성한 요약 결과를 Gmail 본문에 연결
8. 낮은 만족도 테스트 응답 제출
9. AI 요약 이메일 수신 확인

#### 발생한 문제

- HTTP 요청 본문의 JSON 형식 오류
- 설문 응답값을 JSON 문자열에 안전하게 넣는 방법이 명확하지 않았음
- NVIDIA 모델명과 요청 형식이 일치하지 않아 오류가 발생함
- HTTP 응답은 생성되었지만 Gmail 본문에 요약 결과가 표시되지 않는 문제가 있었음
- Make 화면에서 일부 응답 분석 옵션이 보이지 않아 설정 과정이 지연됨

#### 해결 방법

- NVIDIA API 요청 예시에 맞게 모델명과 JSON 구조를 수정함
- HTTP 모듈의 인증 헤더와 `Content-Type`을 다시 설정함
- 설문 개선사항 매핑 위치를 수정함
- NVIDIA 응답 데이터 중 실제 생성 문장이 들어 있는 값을 Gmail 본문에 다시 매핑함
- 단계별 테스트를 반복하여 HTTP 성공 응답과 이메일 결과를 각각 확인함

#### 결과

- 만족도가 `2점 이하`인 응답의 개선사항을 NVIDIA AI가 요약함
- 생성된 요약 결과를 Gmail 본문에 포함하여 발송함
- AI 요약 이메일이 정상적으로 수신되는 것을 확인함

## 5. 프로젝트를 통해 확인한 점

### Make

- 하나의 시나리오에서 Router를 이용한 조건 분기가 가능함
- HTTP 모듈을 통해 외부 AI API를 연동할 수 있음
- 복잡한 자동화와 데이터 처리에 유리함
- 필터, 매핑, JSON 구조에 대한 학습이 필요함

### Zapier

- 단계별 설정 방식이 비교적 단순함
- 기본적인 앱 연결과 이메일 자동화를 빠르게 구현할 수 있음
- 무료 플랜에서는 복잡한 분기와 다단계 자동화에 제약이 있음
- 조건이 늘어나면 여러 개의 Zap을 관리해야 할 수 있음

### 종합 결과

단순한 알림 자동화는 Zapier가 비교적 쉽게 구현되었으며, 복잡한 조건 분기와 외부 AI 연동에는 Make가 더 적합하였다. 같은 업무를 두 도구로 구현하면서 무료 플랜의 차이, 사용량 계산 방식, 확장성 및 사업화 가능성을 비교할 수 있었다.
