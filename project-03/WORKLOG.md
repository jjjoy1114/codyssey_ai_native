# PROJECT 03 작업 기록

## 1. 프로젝트 개요

Google Form으로 프로그램 만족도와 상담 요청을 수집하고, 응답을 Google Sheets에 저장한 뒤 Make와 Zapier를 이용하여 조건별 이메일 알림을 자동 발송하는 프로젝트이다.

Make에는 NVIDIA AI API를 추가로 연결하여 상담을 요청한 응답의 개선사항과 상담 내용을 요약한 뒤 이메일로 발송하는 보너스 기능도 구현하였다.

### 2026-07-25~07-29 — Make 기본 자동화 구현

#### 자동화 구조

```text
Google Form
→ Google Sheets
→ Make Watch New Rows
→ Router
   ├─ 상담 요청 = 예 → Gmail 상담 요청 알림
   └─ 만족도 ≤ 2점 → Gmail 낮은 만족도 알림
```

#### 수행 내용

1. Google Sheets의 `Watch New Rows` 모듈 생성
2. 설문 응답이 저장되는 스프레드시트와 워크시트 연결
3. Router를 추가하여 처리 경로를 두 개로 분리
4. 상담 요청 분기에 `상담 요청 = 예` 필터 설정
5. 낮은 만족도 분기에 `만족도 ≤ 2점` 필터 설정
6. 각 분기에 Gmail 모듈 연결
7. 설문 응답 정보를 이메일 제목과 본문에 매핑
8. `Run once`를 이용하여 조건별 이메일 발송 테스트

#### 발생한 문제

- 초기 설정에서 기존 행과 새 행의 시작 위치를 지정하는 과정이 혼동됨
- Router의 Fallback 안내로 인해 분기 구조를 다시 확인함
- 필터에 표시되는 Google Sheets 열과 매핑값을 찾는 과정에서 어려움이 있었음
- 일부 테스트에서 이메일 제목과 본문이 의도한 값으로 표시되지 않음
- 설정 오류로 Make 시나리오를 새로 작성함

#### 해결 방법

- Google Sheets 연결과 시작 위치를 다시 설정함
- Router의 각 경로에 필터를 개별 적용함
- 실제 테스트 응답을 추가하여 새로운 행이 감지되는지 확인함
- Gmail 제목과 본문 필드를 다시 매핑함
- 상담 요청과 낮은 만족도 조건을 각각 테스트함
- 두 조건을 동시에 충족하는 응답으로 두 분기의 동시 실행을 확인함

#### 결과

- 상담 요청이 `예`인 경우 상담 요청 이메일 자동 발송 성공
- 만족도가 `2점 이하`인 경우 낮은 만족도 이메일 자동 발송 성공
- 두 조건을 모두 충족하면 이메일 두 통이 각각 발송되는 것을 확인함

### 2026-07-29~07-30 — Zapier 자동화 구현

Zapier 무료 플랜에서는 Paths를 이용한 다중 조건 분기가 제한되어 있어, 하나의 자동화를 두 개의 Zap으로 나누어 구현하였다.

#### Zap 1: 상담 요청 알림

```text
Google Sheets 새 행 감지
→ 상담 요청 = 예 필터
→ Gmail 상담 요청 알림 발송
```

#### Zap 2: 낮은 만족도 알림

```text
Google Sheets 새 행 감지
→ 만족도 ≤ 2점 필터
→ Gmail 낮은 만족도 알림 발송
```

#### 수행 내용

1. Google Sheets의 `New Spreadsheet Row` 트리거 설정
2. 설문 응답 스프레드시트와 워크시트 선택
3. 테스트용 설문 응답 불러오기
4. 상담 요청이 `예`인 경우만 통과하도록 Filter 설정
5. Gmail 알림 제목과 본문 매핑
6. 상담 요청 Zap 테스트 및 활성화
7. 기존 Zap을 복사하여 낮은 만족도 Zap 생성
8. 만족도가 `2점 이하`인 경우만 통과하도록 조건 변경
9. 낮은 만족도 Zap 테스트 및 활성화

#### 발생한 문제

- 무료 플랜에서는 하나의 Zap 안에서 두 조건을 자유롭게 분기하기 어려웠음
- Zap 복사 후 일부 필터와 이메일 내용을 다시 수정해야 했음
- 테스트용 응답 선택과 Zap 공개 시점을 구분하는 과정에서 혼동이 있었음

#### 해결 방법

- 상담 요청과 낮은 만족도 알림을 별도의 Zap 2개로 구성함
- 각 Zap의 필터와 Gmail 내용을 따로 설정함
- 테스트 완료 후 두 Zap을 각각 활성화함

#### 결과

- 상담 요청 알림 이메일 수신 성공
- 낮은 만족도 알림 이메일 수신 성공
- 두 조건을 모두 충족하는 응답에서는 두 Zap이 각각 실행되는 것을 확인함

### 2026-07-30~08-03 — NVIDIA AI 보너스 기능 구현 및 오류 해결

Make의 상담 요청 분기에 NVIDIA AI API를 연결하여,
상담이 필요한 응답의 개선사항과 상담 내용을 요약한 이메일을 자동 발송하도록 확장하였다.

#### 최종 자동화 구조

```text
Google Form
→ Google Sheets
→ Make Watch New Rows
→ Router
   ├─ 만족도 ≤ 2점
   │  └─ Gmail 낮은 만족도 알림
   │
   └─ 상담 요청 = 예
      └─ NVIDIA API 상담 내용 요약
         └─ Gmail AI 요약 이메일
```

#### 수행 내용

1. NVIDIA Build에서 사용할 AI 모델 확인
2. Make에 HTTP 요청 모듈 추가
3. NVIDIA API 요청 주소와 인증 헤더 설정
4. 설문 응답의 참여자·프로그램·만족도·개선사항·상담 내용을 프롬프트에 매핑
5. JSON 형식의 요청 본문 작성
6. NVIDIA API 응답 구조 확인
7. AI가 생성한 최종 요약 결과를 Gmail 본문에 연결
8. 상담 요청이 `예`인 테스트 응답 제출
9. AI 요약 이메일 수신 확인
10. 낮은 만족도 분기와 AI 분기가 독립적으로 실행되는지 재검증

#### 발생한 문제

- HTTP 요청 본문의 JSON 형식 오류
- 설문 응답값을 JSON 문자열에 안전하게 넣는 과정에서 오류 발생
- NVIDIA 모델명과 요청 구조 불일치
- AI 경로의 상담 요청 필터 누락
- 낮은 만족도 경로가 Fallback route로 설정되어 일부 조건에서 실행되지 않을 가능성 발생
- HTTP 응답은 성공했지만 Gmail 본문의 AI 요약 결과가 빈칸으로 출력됨
- Gmail 본문 줄바꿈과 HTML 형식이 정상적으로 표시되지 않음

#### 해결 방법

- NVIDIA API 요청 예시에 맞게 모델명과 JSON 구조 수정
- 문자열 매핑과 줄바꿈 형식 수정
- AI 분기에 `상담 요청 = 예` 필터 추가
- 낮은 만족도 분기를 일반 경로로 변경하고 `만족도 ≤ 2점` 필터 직접 적용
- 두 경로 모두 `Fallback route = No`로 설정
- Gmail 본문을 HTML 형식으로 작성하고 줄바꿈 적용
- Make의 `Run once`와 HTTP Output을 이용해 응답 구조 확인

#### AI 요약 빈칸 문제 분석

HTTP 모듈의 Output을 확인한 결과 다음 상태가 나타났다.

```text
choices
└─ message
   ├─ role: assistant
   ├─ content: empty
   └─ reasoning: 긴 추론 내용
```

HTTP 상태 코드는 정상적으로 반환되었지만,
최종 답변이 저장되어야 하는 `message.content`는 빈 값이었다.

사용한 NVIDIA Llama-3.3 Nemotron 모델은 최종 답변을 생성하기 전에
추론 과정을 수행하는 모델이다.

당시 HTTP 요청에서 다음과 같이 설정되어 있었다.

```json
"max_tokens": 180
```

HTTP Output에서 `reasoning`은 생성되었지만 `message.content`가 빈 값으로 반환된 점을 바탕으로,
설정된 출력 토큰이 추론 과정에 대부분 사용되어 최종 요약문 생성 전에 응답이 종료된 것으로 판단하였다.
이를 다음과 같이 수정하였다.

```json
"max_tokens": 2000
```

수정 후 HTTP Output에서 `message.content`가 정상적으로 생성되었으며,
Gmail 본문에도 AI 요약 결과가 빈칸 없이 표시되었다.

#### 결과

- 만족도 2점 이하 응답은 낮은 만족도 이메일만 발송
- 상담 요청이 `예`인 응답은 NVIDIA AI 요약 이메일 발송
- 두 조건을 모두 충족하면 두 분기가 각각 실행
- HTTP 상태 코드 200 정상 확인
- `message.content` 정상 생성
- Gmail AI 요약 이메일 정상 수신
- AI 요약 빈칸 문제 해결


## 4. 최종 구현 결과

| 구분 | 실행 조건 | 자동 처리 결과 |
|---|---|---|
| Make 낮은 만족도 분기 | 만족도 ≤ 2점 | 낮은 만족도 이메일 발송 |
| Make NVIDIA AI 요약 분기 | 상담 요청 = 예 | 개선사항과 상담 내용을 AI가 요약한 이메일 발송 |
| Zapier 상담 요청 Zap | 상담 요청 = 예 | 상담 요청 이메일 발송 |
| Zapier 낮은 만족도 Zap | 만족도 ≤ 2점 | 낮은 만족도 이메일 발송 |

Make와 Zapier 모두 Google Sheets에 저장된 새로운 설문 응답을 정상적으로 감지하였다.

Make에서는 Router의 두 경로를 일반 분기로 구성하였다.

- 만족도 2점 이하 → 낮은 만족도 이메일
- 상담 요청이 예 → NVIDIA AI 요약 이메일
- 두 조건을 모두 충족 → 두 이메일 모두 발송

Zapier에서는 상담 요청과 낮은 만족도 알림을 별도의 Zap 2개로 구성하였다.

- 상담 요청이 예 → 상담 요청 이메일
- 만족도 2점 이하 → 낮은 만족도 이메일
- 두 조건을 모두 충족 → 두 Zap이 각각 실행
